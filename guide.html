    The Shell & Git Field Guide

    Everything from a hands-on Carpentries workshop, rewritten as a guide you can actually learn from: the commands, the reasons behind them, the traps people really fall into, and practice to lock it in. Written for researchers on Windows who use AI assistants and want to know enough to use them wisely.

    Chapter 0

    Start here: why bother?

    The shell looks old-fashioned until you have 500 files to rename, a server with no mouse, or a reviewer asking exactly how a result was produced.

    The one-paragraph version

    The shell is a program where you type commands instead of clicking. Bash is the most common shell and the little language it understands. Git keeps a history of every version of your project. GitHub stores a copy online so you can back up, share and publish. Together they let you do research work that is scalable, repeatable, and explainable.

    Scale

    Clicking works for 5 files. One line of shell handles 5,000 the same way.

    Servers

    HPC clusters and GPU machines have no desktop. The shell is the only way in.

    Everything assumes it

    Git, Python environments, Docker, installers and READMEs are written as shell commands.

    Reproducibility

    Clicks leave no trace. Commands can be saved, re-run and shown to someone else.

    How the pieces fit

    ToolJobAnalogy
    ShellFind, organise and process files; run programs; automateYour hands
    ScriptsSaved sequences of shell commandsA written recipe
    GitHistory of every change; undoA lab notebook that never loses a page
    GitHubOnline copy for backup, sharing, websitesThe shared lab drive
    R / PythonThe actual analysisThe instrument
    Using AI assistants wisely

    AI is great at writing a tricky one-liner, a loop or a regex. It is also often wrong in ways that only the basics reveal: commands for the wrong shell (PowerShell vs bash, Mac vs Linux), the wrong folder, or dangerous "fixes" like chmod 777.

    Do yourself: moving around, looking at files, copying, moving, deleting, the Git cycle. Ask AI for: complex pipelines, loops, regex, unfamiliar tools. Always: read what it gives you and be able to say what each piece does before you press Enter.

    The habit that prevents most problems

    Before you act: where am I? (pwd) → what's here? (ls) → then act. Most errors in this guide come down to skipping that.

    Check the prompt before every session

    If it starts with PS you're in PowerShell, and commands like head, wc and ls -F will fail or misbehave. Open Git Bash from the Start menu instead.

    The OneDrive trap

    On many university laptops the Desktop is quietly moved inside OneDrive, e.g. C:\Users\you\OneDrive - University\Desktop. That causes three problems:

    • ~/Desktop doesn't exist, so tutorial commands fail with No such file or directory.
    • The path has spaces, so every command needs quotes.
    • Cloud sync fights with scripts and Git that change many files quickly (locked files, "-copy" duplicates, corrupted .git folders).
    Fix

    Keep code and data in a short, local, space-free folder such as ~/shell-lesson-data (= C:\Users\you\shell-lesson-data). Back it up with Git and GitHub instead of OneDrive. Run ls ~: if you see OneDrive... but no Desktop, this applies to you.

    Chapter 2

    Where am I? Paths and navigation

    Nearly every "No such file or directory" is really "the computer and I disagree about where I am". This chapter fixes that permanently.

    Core ideas

    • Directory = folder. Same thing.
    • Working directory: the folder you're in right now. Commands act here, and they do not look inside subfolders unless told to.
    • Home ~: your personal folder (/c/Users/you). Git Bash opens here.
    • Absolute path: full address from the top, starts with / or ~. Works from anywhere.
    • Relative path: directions from where you are. Short, but only right from the right starting point.
    • . = this folder, .. = the folder above. Real entries in every folder (ls -a shows them), which is why cd .. works without naming the parent.
    shell-lesson-data/ ├── exercise-data/ │ ├── alkanes/ cubane.pdb ethane.pdb ... (6 molecules) │ ├── animal-counts/ animals.csv │ ├── creatures/ basilisk.dat minotaur.dat unicorn.dat │ └── writing/ haiku.txt LittleWomen.txt └── north-pacific-gyre/ NENE01729A.txt ... (17 files) goostats.sh goodiff.sh

    Commands

    CommandDoesUse it when
    pwdPrint where you are (absolute)Anything "can't be found"
    lsList what's hereConstantly
    ls -FMark folders /, shortcuts @, runnable *Telling files from folders
    ls -aInclude hidden entries (.git, ., ..)Finding config files
    ls -lhLong listing with readable sizesSpotting empty or huge files
    ls -lhrt…sorted by time, newest at the bottom"What did my script just write?"

    Flags

    The -letters after a command change how it behaves, and combine: ls -l -h = ls -lh. Case matters (-F ≠ -f), spaces matter (ls-F = command not found), and lowercase -l looks almost exactly like the number -1.

    Spaces in names

    The shell splits commands on spaces. cd /c/My Stuff/x becomes cd + /c/My + Stuff/x, which fails. Fixes: quotes "/c/My Stuff/x", a backslash /c/My\ Stuff/x, or Tab completion (adds the backslash for you). Tutorials never need quotes because their folder names have no spaces. That's the real lesson: don't put spaces in names.

    Keyboard survival kit

    TabComplete a name. Twice = list the options. Nothing happens = wrong name or wrong folder
    ↑ / ↓Previous commands (edit and re-run instead of retyping)
    Ctrl+CCancel whatever is running or half-typed. Escapes a stuck > prompt
    Shift+InsertPaste in Git Bash

    Practice

    You're in exercise-data/creatures. Get into alkanes with one command. easy
    cd ../alkanes: up to exercise-data, then down into alkanes.
    From alkanes, the tutorial says cd ../north-pacific-gyre and it fails. Why? medium
    Relative paths depend on where you start. north-pacific-gyre is next to exercise-data, not next to alkanes. From alkanes you need cd ../../north-pacific-gyre.
    From your home folder, cd Desktop/shell-lesson-data fails. Name two possible reasons. medium
    (1) Your Desktop lives inside OneDrive, so there's no ~/Desktop. (2) The data isn't on the Desktop at all. ls and pwd tell you which.
    You typed ls oldversions\ and now see > instead of $. What now? easy
    A trailing \ (or an unclosed quote) means "the command continues". Press Ctrl+C to get back to $.
    Chapter 3

    Looking inside files

    A multi-gigabyte CSV can freeze Excel. These commands peek without loading the whole thing.

    CommandDoesReal use
    cat filePrint the whole fileShort files
    head -n 5 fileFirst 5 lines (default 10)Check column headers
    tail -n 5 fileLast 5 linesDid my run finish? Last log line?
    less fileScroll; q quitsReading long files
    wc -l fileCount linesHow many records?
    head -n 2 *.pdbFirst 2 lines of every file, each labelled ==> name <==Check a whole batch at once
    zcat file.gz | headPeek inside a compressed file without unzippingBig downloaded datasets
    Files vs folders: don't trust the name

    A folder can be called number.txt and a file can be called c. ls -l tells the truth: first character d = folder, - = file. cd only works on folders; cat/head only on files. Extensions are just part of the name: copying draft.txt to draft.mp3 doesn't make it audio, and renaming data.csv to data.xlsx doesn't make it Excel.

    From alkanes, head unicorn.dat says "No such file". Fix it without moving. easy
    head ../creatures/unicorn.dat. The file lives in a sibling folder.
    Chapter 4

    Pipes and redirection: snapping tools together

    Each command does one small thing. The power comes from connecting them, like LEGO.

    SymbolNameDoes
    |PipeSend one command's output into the next command
    >RedirectSave output to a file. Overwrites without asking
    >>AppendAdd output to the end of a file
     
    wc -l *.pdb                              # count lines in each file (+ a total)
wc -l *.pdb | sort -n                    # ...ranked smallest first
wc -l *.pdb | sort -n | head -n 1        # ...just the smallest
wc -l *.pdb > lengths.txt                # save instead of printing
grep -n not haiku.txt                    # lines containing "not", with line numbers
grep -c -i error *.log                   # how many lines mention error, per file
    grep flagMeans
    -iIgnore upper/lower case
    -nShow line numbers
    -cCount matching lines
    -wWhole word only
    -vLines that do NOT match
    The silent file-eater

    sort data.txt > data.txt leaves you with an empty file: > empties the target before sort reads it. Always redirect into a new name.

    Two meanings of > and $

    When the shell prints > or $, it's a prompt waiting for you. When you type them, > redirects output and $name means "the value of the variable".

    Make lengths.txt with the .pdb line counts but without the "total" line. Two ways. medium
    wc -l *.pdb | head -n 6 > lengths.txt          # in one go (6 files, total is line 7)
wc -l *.pdb > all.txt; head -n -1 all.txt > lengths.txt   # from a saved file
    head -n -1 = all but the last line (works for any number of files). grep -v total also works.
    Chapter 5

    Wildcards: many files, one command

    Research data comes in batches with patterned names. Consistent naming + wildcards = act on hundreds of files at once.

    PatternMatchesExample match
    *Any characters, including none*.pdb → every .pdb file
    ?Exactly one characterdraft_v?.txt → v1, v2, but not v11
    [cp]One character from the set[cp]*.pdb → starts with c or p
    p*.txtStarts with p AND ends with .txtNarrower than p*
    *2*Contains a 2 anywherepropane2.txt
    */*.txt.txt files one folder downWildcards don't search deeper on their own

    The shell expands the pattern into a list of names before the command runs: wc -l p*.pdb becomes wc -l pentane.pdb propane.pdb. That's why echo pattern or ls pattern previews exactly what will be affected.

    Safe habit for anything destructive

    1. ls pattern   2. read the list   3. swap ls for rm/mv/cp with the exact same pattern.

    From exercise-data, ls p*.pdb finds nothing, even though the files exist. Why? easy
    They're one level down in alkanes. Wildcards only match in the current folder. Use ls alkanes/p*.pdb.
    Files: draft_v1.txt draft_v2.txt draft_v10.txt draft_final.txt. What do draft_v??.txt and *v1* match? medium
    draft_v??.txt → draft_v10.txt. *v1* → draft_v1.txt and draft_v10.txt.

    Chapter 7

    Counting, sorting and pulling out columns

    Instant answers about a dataset (how many rows, which categories, how often) before you even open R.

    CommandDoes
    wc file / wc -lLines, words, characters / lines only
    sort / sort -nSort as text / as numbers. Without -n, 107 sorts before 12
    cut -d , -f 2 file.csvKeep column 2 (-d = delimiter, -f = field). -f 2,3 or -f 1-2 for several
    cut -f 2 file.tsvTab-separated: leave out -d, tab is the default (or -d $'\t')
    uniq / uniq -cCollapse neighbouring duplicates / and count them
    sort -uSort + unique in one step (can't count)
     
    cut -d , -f 2 animals.csv | sort | uniq -c    # instant frequency table
      1 bear
      2 deer
      1 fox
      3 rabbit
      1 raccoon
    Why uniq needs sort

    uniq only compares each line with the one right before it. Unsorted deer, rabbit, raccoon, rabbit, deer has no identical neighbours, so nothing is removed. sort groups them first.

    Gotchas

    cut -d \t is not a tab: the shell turns \t into the letter t, nothing splits, and the whole line prints.

    Asking for a column that doesn't exist gives no error, just less output. A typo in a column number won't warn you.

    cut splits on every comma, including commas inside quoted text ("Moscow, ID"). For messy real CSVs, use R's read.csv.

    uniq -c catches messy categories: Rabbit and rabbit appear as separate lines.

    Pull the year out of the date 2012-11-05 with one command. medium
    echo 2012-11-05 | cut -d - -f 1 → 2012. Any single character can be a delimiter.
    Chapter 8

    File permissions

    Irrelevant on your own laptop, essential on shared servers: who can read your data, who can change it, and whether a script may run.

    Every file has an owner, a group (a named team, e.g. a lab; check yours with groups), and permissions for owner / group / everyone else.

    -rwxr-x--- │└┬┘└┬┘└┬┘ │ │ │ └─ others: nothing │ │ └──── group: read + run │ └─────── user: read + write + run └───────── type: - file, d directory
    LetterOn a fileOn a folder
    rRead contentsList what's inside
    wChange / deleteAdd or remove files
    xRun as a programcd into it

    chmod

    CommandMeans
    chmod +x script.shMake runnable. Fixes "Permission denied" when running your own script
    chmod g+r file / chmod o-r fileGroup can read / others can't
    chmod g-w rawdata/*Protect raw data from accidental edits by the group
    755 = rwxr-xr-xScripts others may run, not edit
    644 = rw-r--r--Normal files
    700 / 770Private / shared with group only
    Never chmod 777

    It's a common "quick fix" online and from AI for permission errors. On a shared machine it means anyone can change or delete your files. The real fix is usually u+x or a group permission.

    How it looks in different places

    WhereWhat to expect
    Windows, Git BashPermissions are guessed: files starting with #! show x; chmod visibly does nothing. If a script won't run: bash script.sh
    Windows, WSL on /mnt/cEverything shows rwxrwxrwx (also faked)
    Your HPC home folderReal and enforced; usually private to you
    Your lab's project folderOwned by a lab group, e.g. drwxrws---. The s (setgid) makes new files belong to the group automatically, so labmates can always open them
    Scratch spacePrivate, fast, often auto-deleted. Never keep the only copy there
    What does -rwxr-x--- let each person do? easy
    Owner: read, write, run. Group: read and run. Others: nothing (750), a typical "shared with my lab only" script.
    Chapter 9

    Loops: do it once, apply it everywhere

    The moment the shell starts saving you real time: one command, run once per file, the same way every time.

    for filename in *.dat
do
    echo $filename
    head -n 2 $filename | tail -n 1
done
    for filename in ...Go through the list; each time, store the current item in a variable called filename
    do … doneThe commands to repeat
    $filenameThe value stored in the variable
    The listTyped out, a wildcard (*.dat), or a sequence ({1..10}, {01..12}, {10..1})

    One-line version: for f in *.dat; do echo $f; done. Semicolons go after the list, between commands, and before done. Tip: type the multi-line version once, press ↑, and bash shows it as one line with the semicolons in place.

    The classic mistake

    for f in *.pdb; do ls *.pdb; done lists all six files six times: it never uses $f. If your loop body doesn't mention the variable, it's probably wrong.

    Dry-run anything dangerous

    Put echo in front: for f in *.dat; do echo cp $f backup-$f; done prints the commands instead of running them. Looks right? Remove echo.

    Patterns you'll reuse

    for f in *.dat; do cp $f original-$f; done                 # backups (cp *.dat original-*.dat can't do this)
for f in *.pdb; do cat $f >> all.pdb; done                 # combine: >> not > (or only the last survives)
for f in "cool basilisk.dat" "pink unicorn.dat"; do head "$f"; done   # names with spaces need quotes
for s in cubane ethane methane; do                        # nested: 3 x 4 = 12 folders
    for t in 25 30 37 40; do mkdir $s-$t; done
done
    Why does cp *.dat original-*.dat fail with "not a directory"? medium
    With several source files, cp needs the last item to be a folder. Building a new name per file needs a loop: for f in *.dat; do cp $f original-$f; done.
    Print 0 to 9 the lazy way. easy
    for n in {0..9}; do echo $n; done. {0..9} is brace expansion.
    Chapter 10

    Shell scripts

    A script is just the commands you'd type, saved in a file, so anyone (including future you) can re-run them exactly.

    #!/bin/bash
# select lines from the middle of a file
# usage: bash middle.sh filename end_line num_lines
head -n "$2" "$1" | tail -n "$3"
    #!/bin/bashShebang: which program runs the file
    # ...Comments for humans: what it does and how to call it
    $1 $2 $3The 1st, 2nd, 3rd arguments typed after the script name
    "$@"All the arguments, however many
    $#How many arguments there were
    "$1" in quotesKeeps file names with spaces in one piece
    name="value"Create a variable (no spaces around =)
    $(date)Insert a command's output, e.g. a timestamp in a log

    Three ways to run a script

    You typeResultWhy
    myscript.shcommand not foundThe shell only searches system folders (the PATH), not the current one. A safety feature
    ./myscript.shRuns./ = "the one right here". Needs x permission
    bash myscript.shRunsHands it to bash directly; doesn't need x
    Match the runner to the language

    bash x.sh, python x.py, Rscript x.R. bash can't read Python.

    Read before you run

    less script.sh takes ten seconds and tells you exactly what a script (from a colleague, the internet, or an AI) is about to do. Good scripts check their inputs and print a usage message when called wrong, like goodiff.sh does with no arguments.

    Capstone: a setup script that logs itself

    #!/bin/bash
# build experiment folders and record what was created
log_file="setup_log.txt"
echo "Setup started: $(date)" > $log_file
for species in cubane ethane methane; do
    mkdir -p $species
    echo "Created $species" >> $log_file
    for temperature in 25 30 37 40; do
        mkdir -p $species/$temperature
        touch $species/$temperature/experiment.sh
        echo "  - $species/$temperature/" >> $log_file
    done
done
echo "Setup completed: $(date)" >> $log_file

    Notice: > once to start a fresh log, >> after that; mkdir -p so re-running doesn't fail with "File exists".

    Write sorted.sh that ranks any files you give it by length. medium
    #!/bin/bash
# usage: bash sorted.sh file1 [file2 ...]
wc -l "$@" | sort -n
    Then bash sorted.sh *.pdb ../creatures/*.dat.
    Write species.sh: for each CSV given, print its unique species (column 2). harder
    #!/bin/bash
for file in "$@"; do
    echo "Unique species in $file:"
    cut -d , -f 2 "$file" | sort | uniq
done
    Inside a file you don't type the > prompts; those only appear when typing a loop interactively.
    Chapter 11

    Remote servers: SSH, file transfer and SLURM

    This is where everything earlier pays off. A cluster or GPU server is just a shell on a much bigger computer.

    Logging in

    ssh username@server.university.edu                         # prompt changes to username@server
ssh -o ServerAliveInterval=60 username@server.university.edu   # keep-alive: idle connections don't drop
exit                                                       # back to your laptop
    Always know which computer you're typing into

    username@server = the server. MINGW64 = your laptop (Git Bash). PS C:\ = your laptop (PowerShell). If the connection resets, you silently land back on the laptop. Start ssh from Git Bash so a drop leaves you in a bash shell.

    The login banner is worth reading: core count, memory, current load, the support contact, and maintenance windows (e.g. a weekly reboot that will kill long jobs left running).

    Moving files

    scp results.csv username@server:~/project/        # upload (last item = destination)
scp username@server:~/project/results.csv .       # download to here ( . = current folder)
scp -r username@server:~/project .                # a whole folder

    FileZilla and WinSCP do the same thing with drag-and-drop (SFTP runs over SSH). Web portals like Open OnDemand give you files, a terminal and RStudio/Jupyter in the browser; if one won't load, try the campus VPN, and if login is refused, ask research computing support to enable it for your account.

    Looking around a shared machine

    who / w / usersWho is logged in (w adds what they're running and the load)
    top / htopLive CPU/memory per process and user (q quits)
    nvidia-smiGPU memory, load and processes. Check before starting a big GPU job
    df -hHow full the disks are
    last | headRecent logins

    Logging in without a password every time

    ssh-keygen -t ed25519                      # make a key pair on your laptop (Enter for defaults)
ssh-copy-id username@server.university.edu  # put the public half on the server

    Two-factor (e.g. Duo) may still be required by policy. Ask your research computing team; don't try to get around it. A ~/.ssh/config entry lets you type ssh myserver instead of the full address.

    SLURM: the queue

    Clusters are shared, so heavy work is submitted as a job and run when resources free up, like a restaurant waiting list.

    Node / partitionOne computer / a group of nodes for a purpose (gpu, short)
    Login vs compute nodeLogin: edit and submit only. Compute: where jobs run
    sinfoPartitions and node status
    squeue / squeue -u meThe queue / your jobs. R running, PD pending
    Waiting reasons(Resources) not enough free; (Priority) others first; (Dependency) waiting for another job (pipelines); (QOS…Limit) hit your limit
    sbatch job.sh / scancel IDSubmit / cancel
    srun --pty bashInteractive shell on a compute node for testing

#SBATCH --partition=gpu
#SBATCH --cpus-per-task=4
#SBATCH --mem=16G
#SBATCH --gres=gpu:1
#SBATCH --time=02:00:00
#SBATCH --output=log_%j.txt
python train_model.py

    Chapter 12

    Git: your project's memory

    Undo mistakes, see exactly what changed and when, prove how a result was produced, and keep laptop and server in sync.

    Working directory ──git add──▶ Staging area ──git commit──▶ Repository (history) (you edit) ("in the box") ("box sealed + labelled")

    Start a repository

    cd ~/my-project          # NOT inside OneDrive, NOT inside another repo
git init
git branch -M main       # older installs default to "master"; GitHub uses "main"
ls -a                    # .git/ holds the whole history. Never edit or delete it

    Inside a repo, Git Bash shows the branch in the prompt, e.g. (main). Handy sign you're in one.

    The everyday cycle

    git status                       # what changed? (run it constantly, like pwd)
git add -A                       # stage everything (or: git add file.txt)
git status                       # confirm what's staged
git commit -m "what and why"     # save the snapshot
git log --oneline                # history
    Untracked ──add──▶ Staged ──commit──▶ Tracked ──edit──▶ Modified ──add+commit──▶ saved again
    Reading the outputMeans
    [main (root-commit) f566a1b]Branch, very first commit, commit ID
    create mode 100644Permissions rw-r--r-- (Chapter 8)
    LF will be replaced by CRLFWindows line-ending conversion. Normal; ignore
    filter.lfs... in configGit LFS for large files, often added by GitHub Desktop. Harmless

    .gitignore: decide what Git should never see

    *.gz
*.fasta
results/
.Rhistory

    Patterns use shell wildcards. The .gitignore itself is committed, so collaborators share the rules.

    A real near-miss

    A 90 MB protein database (uniprot_sprot.fasta.gz) was downloaded into a repo and git add -A ran before any .gitignore existed, so it got staged. Caught before committing:

    nano .gitignore                         # add *.gz and *.fasta
git rm --cached path/to/uniprot_sprot.fasta.gz   # unstage, keep the file on disk
git add .gitignore
git check-ignore -v path/to/uniprot_sprot.fasta.gz   # .gitignore:1:*.gz → ignored
git commit -m "first commit, ignore large sequence files"

    Rule: create .gitignore before the first git add. GitHub warns at 50 MB and rejects files over 100 MB. Track code, not big data.

    Best practices

    • git status before and after everything; read it before git add -A.
    • Small, frequent commits with messages that say what and why ("fix date parsing", not "update").
    • git pull before you start; git push when you stop. Commits live only on your laptop until pushed.
    • Never commit passwords or keys. A pushed secret is a leaked secret: change it.
    • One repo per project; no repos inside repos; no repos inside OneDrive/Dropbox.
    "Please tell me who you are" on the first commit. Not logged in? easy
    No: Git needs a name and email to label commits. git config --global user.name "..." and user.email "...". Logging in to GitHub only happens at git push.
    "key does not contain a section"? easy
    A typo in the setting name. It must be user.name / user.email (with the dot), with the value in quotes.
    Chapter 13

    Time travel: history, differences and undo

    "Five versions ago it worked better." Find it, look at it, compare it, bring it back, without losing anything.

    Find and compare

    QuestionCommand
    Which versions exist?git log --oneline file.sh
    …with the actual line changesgit log -p file.sh
    What did version X look like? (changes nothing)git show X:file.sh
    What have I changed since my last commit?git diff
    Version X vs now / X vs Ygit diff X file.sh / git diff X Y file.sh

    HEAD = latest commit, HEAD~1 = the one before, HEAD~5 = five back, or use an ID from git log --oneline. In diffs, red - lines were removed and green + lines added. Good commit messages are what make old versions findable.

    Every common "go back" case

    SituationCommandNote
    Undo my uncommitted edits to a filegit restore fileBack to last commit; edits lost
    One file back to an older versiongit restore --source HEAD~1 fileThen add + commit. History kept
    Browse the whole project in the pastgit checkout X"Detached HEAD" = visiting. Return: git switch main
    Undo a commit that's already pushedgit revert XAdds an "opposite" commit. Safe
    Throw away everything after Xgit reset --hard X⚠ Local, unpushed only
    Unstage a file added by mistakegit restore --staged fileEdits kept
    Deleted a file by accidentgit restore file
    Put changes aside for a momentgit stash / git stash pop
    Fix the last commit messagegit commit --amend -m "..."Not if pushed
    Forgot a file in the last commitgit add f + git commit --amend --no-editNot if pushed
    Undo last commit, keep the changesgit reset --soft HEAD~1Not if pushed
    "I lost commits!"git reflogEverywhere HEAD has been
    The filename says which file; --source says which version

    git restore notes.txt → latest commit. git restore --source HEAD~1 notes.txt → one further back. Mind the spelling: --source with no space after the dashes.

    The golden rule

    Already pushed? Use git revert or restore-and-commit. Never reset --hard or --amend history other people already have.

    Try it: build a two-version file and travel between them. medium
    mkdir ~/restore-practice && cd ~/restore-practice && git init
echo "version A" > notes.txt; git add notes.txt; git commit -m "A"
echo "version B" > notes.txt; git add notes.txt; git commit -m "B"
echo "messy edit" > notes.txt
git restore notes.txt;                     cat notes.txt   # version B
git restore --source HEAD~1 notes.txt;     cat notes.txt   # version A
git show HEAD~1:notes.txt                                  # look without changing
cd ~ && rm -rf restore-practice                            # clean up
    Chapter 14

    GitHub: backup, sharing and a free website

    Local Git works offline and only you see it. A remote on GitHub gives you backup, collaboration, and syncing between laptop and server.

    Push an existing local repo

    1. On github.com: + → New repository → name → leave README, .gitignore and license unticked → Create → copy the HTTPS URL.
    2. In the repo folder:
    git status                         # clean? commit anything staged first: push sends commits only
git remote add origin https://github.com/USER/REPO.git
git remote -v                      # check ("origin" is just a nickname)
git push -u origin main            # browser sign-in pops up the first time

    After that, plain git push. The other route for new projects: create on GitHub first, then git clone URL and work inside the clone. Clone the same repo on your laptop and a server: write locally, push, pull on the server, run there.

    Publish a website with GitHub Pages

    1. Add an index.html (home page) and any other pages (gapminder.html → /gapminder.html).
    2. git add → git commit → git push.
    3. Repo Settings → Pages → Deploy from a branch → main / (root) → Save.
    4. Wait 1–2 minutes (Actions tab shows the build), open https://USER.github.io/REPO/, press Ctrl+F5.
    Getting a 404?

    It almost always means the file isn't on GitHub yet. Check git status (?? untracked or M modified means not committed) and git log --oneline, then look at the file list on GitHub. Files reach the website only after add → commit → push. Free accounts need the repo public for Pages.

    This guide and the Gapminder Explorer are published exactly this way. The explorer was this workshop's AI-assisted exercise (the class used the Goose agent): describe the page you want, review the code, then commit and push it yourself.

    Chapter 17

    Final self-check

    Answer out loud before opening each one. If you can explain all ten, you could teach this.

    1. What's the difference between > and >>? And between the > you type and the one the shell shows?
    Overwrite vs append. Typed > redirects output; a printed > is a prompt waiting for you to finish the command.
    2. Why does uniq need sort?
    It only removes duplicates that are next to each other.
    3. Inside a script, what are $1, "$@"? Inside a loop, $filename?
    First argument; all arguments; the current item of the loop.
    4. Give three reasons for "No such file or directory".
    Wrong folder; typo; file one level deeper (or a path with an unquoted space).
    5. When do you need a loop instead of a wildcard?
    When each file needs its own new name or its own command, e.g. cp $f original-$f. cp *.dat backup/ works with a wildcard alone.
    6. Why keep research code and data out of OneDrive?
    Spaces in paths, long paths, and cloud sync conflicting with scripts and Git (locked files, duplicates, corrupted .git). Use Git + GitHub for backup.
    7. Your script says "Permission denied" on a cluster. Two fixes? And the fix not to use?
    chmod +x script.sh or bash script.sh. Never chmod 777.
    8. You committed and pushed a bad change. How do you undo it?
    git revert <id> (or restore the file from an older commit and commit that). Not reset --hard.
    9. A 90 MB file just got staged. What do you do before committing?
    Add its pattern to .gitignore, git rm --cached it, git add .gitignore, check with git check-ignore -v, then commit.
    10. Your GitHub Pages URL gives 404. First two things you check?
    git status (is the file untracked/modified?) and whether it's in the GitHub file list (was it pushed?). Then Settings → Pages.
